# 学习与培训文档编写

## 目标与范围

让目标读者从已声明的知识和资源起点，独立完成可验证的学习成果，无需讲师补齐关键概念、步骤或判断依据。成果可以是解释概念、完成推导、作出有依据的判断，也可以是运行程序、操作工具或完成业务流程。

适用于软件、命令行、硬件、业务流程和非技术知识学习。先确认主题与交付物，再选择规则：没有界面就不要求菜单和截图；没有多人协作就不强设角色交接；没有部署任务就不创建部署目录。尊重用户已有结构和交付语言。

本技能负责教学内容与组织，不替代特定领域的事实来源，也不单独承担 Word、PDF 或演示文稿的排版与导出；需要这些格式时结合当前环境可用的工具处理。

作者必须核实重要页面、权限、对象和参数的实际系统、功能及产生／维护入口。正文按读者职责说明：消费者只需在前置条件知道谁已提供什么及在哪里使用，上游生产过程留在设计或作者证据层，不要求消费者学习。对读者负责的操作，不能用“业务模块提供”“系统自动生成”“管理员授权”等泛称代替必要来源；陈述式改写保留其适用的事实与边界。按 [authoring-standard.md](references/authoring-standard.md) 的“概念与对象来源”逐点核查。

## 用户操作文档先让人看懂

用户需要找到入口、照着操作、知道完成后会看到什么。作者承担查代码、确认事实和整理流程的工作，不让用户理解实现后再自行拼出操作顺序。下文来源、边界和证据要求由作者核实，客户正文只保留影响当前操作的信息。

- 用屏幕上的菜单、按钮、字段和状态写短句。写“选择产品，填写设备名称，点击 **确定**”，不写“准备上游数据、创建设备实例并完成标准消息验收”。必要术语在第一次使用处用一句话解释。
- 每段解释先问：删掉后，用户是否会选错、操作失败、找不到入口，或忽略重要后果？不会就删除；会就写清选择条件、操作方法或后果。不要把多余说明搬进提示框继续保留。
- 保留必要输入、点击路径、选择依据、确认动作和可见结果。精简核验要求时不能删掉“打开 **设备数据 > 属性**”“点击图表入口查看历史”等实际操作。
- 简洁不能省掉独立功能的操作。同一页面包含终端、网页访问、桌面或文件管理等不同任务时，分别给出短步骤和对应页面图；命令查询配实际输入输出图，不能用未启动界面代替。仅有连接表单时，图注只说明连接入口，实际结果缺口留在作者记录。
- 可替代的方式写成“选择其中一种”，不要编号成必须全部执行的步骤。普通连续点击合并，复杂配置再分步，不按字数或固定层级扩写。
- 默认值、字段来源、角色差异和后台处理仅在改变当前动作时解释。系统生成且无需用户处理的值不必解释生成原理；他人提供的产品或模板只写在哪里选择，缺失时找谁补齐。
- 说明选择器的数据来源时，追查实际查询及其提供方，区分可选资源、当前项目已安装资源和执行端资源；“已启用”“已发布”“已安装”分别核实，不能由按钮名称或旧文档推断。正文只保留读者需要的来源，接口和过滤依据留在作者记录。
- 删除作者调查、接口与持久化检查、内部组件、旧页面对照、穷举可选字段及重复否定。结果写“设备已出现在列表，可查看上报数据”，不要求用户逐字段比对或反复刷新验收实现。
- 提醒只留具体影响，如“停用会断开设备连接”。删除、控制、费用等重要后果仍须说清。异常写“出现什么情况、怎么处理”，不强套四段排查模板。
- 精简时同时核对有效高亮：适用的授权与数据差异仍用 `info`，重要风险用 `warning`，危险操作或严重错误用 `error`；不能只保留原句却把提醒降成普通正文。按 [authoring-standard.md](references/authoring-standard.md) 的“全文概述与语义高亮”筛选，不为每篇凑齐三类。
- 用户确认功能已禁用时，删除对应操作和引导，按当前可用流程改写；保留必要控件原名，不能从历史截图推断功能仍开放。
- 批量修改逐篇读完整正文，保留业务条件、菜单按钮原名、图片及必要恢复链接；不按关键词批量删句，不为统一模板补废话。检查图片前的文字仍能引导用户到达对应页面。

交付前从用户视角走读：不懂实现的人能否顺着文字完成操作？若仍需解释抽象词、筛选无关说明或猜测下一步，继续改写。

## 先确定交付物

| 类型 | 要解决的问题 | 组织方式 |
| --- | --- | --- |
| 课程教材／培训课程 | 新手怎样从起点达到可证明的能力？ | 学习地图、连贯案例、分单元教学、独立练习、结业验收。 |
| 学习指南 | 应先学什么，为什么，学到什么程度？ | 知识依赖、推荐顺序、资料入口、阶段自测与实践路径。 |
| 操作手册 | 已知目标后，怎样完成一项具体任务？ | 已确认的前置、完整业务动作与即时反馈、宏观结果、必要恢复。 |
| 功能配置说明 | 某项配置使哪些功能可用，值从哪里来，如何生效？ | 消费功能与效果、参数来源、配置动作、功能验证、证据边界。 |
| 常见问题合集 | 某业务域的功能出现症状时怎样定位和恢复？ | 按功能点分区，列出现象、检查、处理和复测。 |
| 概念／功能参考 | 一个概念、字段、规则或选项是什么意思？ | 定义、边界、关系、例子与反例、适用限制，链接实践课。 |
| 大纲／骨架 | 后续应编写什么，哪些事实仍待验证？ | 每节目标、前置、内容要点或任务链、计划的证据与练习、待核实项。 |

先完成用户要求的类型和范围。参考资料集合不等于课程；只要求大纲时，不扩写为未经验证的完整教材。理论课程不强套操作手册标题，单篇参考不强加整套课程练习。

软件产品操作手册只收录真实可执行操作；概念及未开发／未开放边界归产品设计或原理参考，并明确标注具体范围与状态，不在操作目录内另设功能参考区。整理此类内容时，读取 [authoring-standard.md](references/authoring-standard.md) 的“操作与设计边界的归属及状态”。

通用软件操作手册按实际系统和菜单树组织，使用可复用的填写与选择规则，不引入取证项目、特定应用或演示案例。角色名称本身不构成分册依据；相同流程按实际所需权限统一说明。正文不写作者验收范围、待核实状态或代码实现细节，核查记录与阻塞保留在作者证据和交付说明中。编写或重排这类手册时，读编写标准中的“通用软件操作手册”。

## 建立教学约定

从请求和可用资料中明确以下事实；只询问无法合理确定且会影响内容的缺口：

1. **读者起点**：已有知识、实际职责或身份、可用工具与资源。
2. **学习成果**：读者最终能解释、判断、制作或完成什么，如何检验。
3. **起始条件**：哪些概念尚未学过，哪些材料或数据尚未准备，哪些资源已经具备。
4. **教学案例（课程或用户要求案例时）**：一个连贯且足够小的场景，使用中性示例，不把示例命名当作真实业务规则。通用操作手册使用选择规则，不默认加入案例。
5. **边界与依据**：主题范围、适用版本、运行条件、来源与已知限制。
6. **交接关系（如有）**：谁提供输入、谁完成动作、谁接收什么结果、在哪里验收。

区分“需要理解某关系”和“必须完成某操作”。不了解概念时推荐前置阅读，不把“已阅读某文档”写成无依据的强制条件。当前课程要生成的成果不能被列为起点已存在的条件。

## 组织学习路径

设计课程、知识顺序、角色单元或练习时，读 [course-design.md](references/course-design.md)。

- 先画出成果和依赖，再拆单元；目录、菜单或术语表都不是默认学习顺序。
- 区分知识前置与实际执行前置。独立分支可以并列，循环引用不代表循环学习依赖。
- 在概念首次影响理解或选择时解释它，给出来源、适用范围和例子；不要开头堆满术语，也不要把当前决定必需的信息全部藏在链接里。
- 一课围绕一个能力或不可拆的任务。合并只提供低信息准备动作的碎片，保留有独立判断、边界、产出或恢复路径的单元。
- 课程先提供示范，再让读者在变化情境下独立练习，最后按可观察标准验收。只换名称并照抄点击不算独立练习。

## 编写正文与资料库

编写正文、建立大纲或调整目录时，读 [authoring-standard.md](references/authoring-standard.md)。它是结构、步骤、字段说明、目录压缩和关联链接的维护入口。按用户指定环境或项目整理菜单时，另读其中“按目标环境对齐菜单”；只读取证按“截图与图注”核对页面隐式写入。产品级资料按“产品级资料的完整性”核对覆盖；标题与入口位置按“命名与编号”执行；FAQ 不追加推荐学习或功能点目录。

拆分产品文档工程、整理客户与作者资料、调整快速入门归属或规划平台与 AI 集成时，再读该标准的“产品文档拆分、发布与持续建设”。按产品读者和实际任务定归属，独立工程保全依赖与附件；默认显示标题无排序序号，排序字段必须接入实际目录与索引。占位展示、可信语料和业务验收分开，持续维护与首批交付后的集成按依赖并行。

正文排版按该标准的“全篇扫读与列表表达”执行：有先后顺序用有序列表，并列事项用无序列表，不用分号把多个步骤、条件或处理方式挤成长段，也不把长段原样搬进单个列表项。

把 Markdown 资料发布为独立 HTML 文档站时，读取该标准中的“Markdown 渲染与站点导航”和“命名与编号”。复用成熟渲染引擎及其目录、搜索、图谱能力，以 Markdown 为内容来源，避免维护另一套手写 HTML 或图谱数据。仅编写 Markdown 时无需新增站点。软件角色目录调整仍先核实实际授权与独立任务，问答排版按“功能配置与常见问题”保留诊断内容和有效锚点。

编写软件产品的功能配置或排障合集时，读取该标准中的“功能配置与常见问题”。这类材料按实际功能依赖相互直链；不把配置正文写成操作手册，也不把 FAQ 当成部署阅读指南。只有用户需要这些材料时才使用该结构。

重构跨功能资料库时，先读编写标准中的“功能归属与文档边界”：依据实际消费链判断每篇负责的输入、动作和结果，再决定前置、正文与关联链接。不能因两个功能共享页面、服务或业务场景，就把一方的配置和验收写成另一方的职责。

完整操作手册先遵守当前用户／项目已确认的结构；没有约定时，可用 `概述`、`前置条件`、`操作步骤`、`结果验证`、`注意事项` 作为起始模板。完整性看必要前置、可执行动作、可见结果与相关风险，不机械以标题数判定。用户取消独立“结果验证”时，结果随步骤与匹配截图说明，不恢复章节或要求读者重复作者核验。注意事项写重要限制与操作后果；异常症状、恢复办法和 FAQ 链接按需放入“常见问题”或恢复分支。配置文档的功能验证仍按其用途保留。只展示信息的概览或仪表盘按页面介绍写用途、展示内容、数据来源和业务入口，配一张真实页面截图即可；不强加步骤、验证和注意事项。概念课改用适合主题的概念解释、示例推演、自测等结构。概述只说谁学什么、做什么、得到什么，不写营销价值。

用户明确只要求简单截图说明时，使用必要入口、真实截图和简短图注，不强套完整任务结构，不扩写未经验证的配置诊断。截图说明完成不代表未测试的业务闭环已验收。

软件产品的操作手册区分读者动作与作者核验：正文不让读者保存后重开、刷新或逐字段比对来替作者验证实现。操作步骤只写完成业务所需动作和即时反馈；结果说明随步骤、图注或约定的独立章节，宏观说明页面能显示相应数据或业务处理能继续。配置加载和链路核实由适用的配置说明承担。

操作步骤按读者实际执行顺序，写清位置或输入、动作、关键选择、立即结果及下一步。复杂动作采用“一个任务目标的一级摘要 + 完整的二级动作”，保留影响结果的选择与恢复入口。非动作解释放在引用块、图注或表格，避免编号假步骤。

参数表用于比较重要选择、追溯来源或解释边界；普通名称、编码或显然的必填信息直接写入操作句。概念、字段、默认值和自动产生的结果需要说明来源及限制，不用“按需选择”“自动生成”代替读者需要的判断依据。

## 文档配图、画图与插图

制作、修改、审查 AI 生成的 SVG 业务配图或沉淀画图规范时，读取 [business-diagrams.md](references/business-diagrams.md) 并查看其中附带的 E-01 SVG 参考素材。该规范替代旧画图经验，统一 1920×1080 画布、字体层级、色板、组件、布局和验收要求。所有流程图遵循完整标准，非流程图保持其真实关系语义。明确的文字规格优先于示例中的个别历史取值；严格保留业务节点、标题、连接、条件、状态及先后顺序。真实操作截图仍作为事实证据，不重绘成此风格。

## 事实与证据

按任务选择可用且适合的证据：权威资料与可核对的推导、实际命令输出及产物、真实界面截图、现场记录或测量结果。为关键结论或任务列出“声明—证据—验收方式”，常规内容无需机械建表。

- **概念教学**：核对定义、前提、推理、例子和反例；有争议或版本相关的说法注明来源与边界。原创教学示例标明假设，不能冒充实测数据。
- **命令行／代码**：写明工作目录、必要依赖、命令、输入、预期输出与错误恢复。若执行已获授权且环境可用，验证关键命令；未执行就标为预期输出，不声称已运行。
- **界面操作**：每篇完整界面操作手册都必须在正文嵌入匹配的真实产品截图；复杂表单、权限选择、关键分支、异常恢复或交接结果分别覆盖其必要状态，图片紧邻对应步骤并有简短图注。简单动作可由相邻截图支持，不要求逐点击配图，但不能因此让整篇没有截图。浏览器或桌面工具按目标环境选择，不限定 Chrome。
- **实体操作**：按适用规范说明材料、仪器、操作条件和观察结果。无法接触设备或现场时区分文献依据与尚未验证的实际操作。

图示、模型和模拟可用于解释，但必须明确用途，不能冒充真实运行、实际页面或已完成的物理实验。照片或截图只能证明画面中可见的事实；保留真实空态、错误态和角色差异。遮蔽凭据和不应公开的个人或客户信息。

菜单可见、按钮可操作和数据可读分别核对。解释菜单显示或隐藏时，追踪目标产品实际存在的功能开放条件、身份或关系授权、父目录补齐、隐藏标记、访问上下文及特殊授权，再比对部署版本及真实页面；不预设每个产品都存在项目、模板或订阅机制，当前源码不能单独证明部署行为。操作图注只说明控件和可见状态，详细声明与证据映射放作者记录。

事实核对以当前任务适用的来源为准：软件可检查界面、代码、接口和官方文档；非软件主题使用对应领域资料，不能凭经验编造来源或结论。产品专属规则由目标项目资料提供，不把某个系统的角色、数据层级或部署模型当作通用知识。

编写请求本身不授权生产变更、付费、对外发送或危险实验。只在已授权的范围中准备演示材料和采集证据。

## 验证与交付

交付前读 [quality-gate.md](references/quality-gate.md)，按交付类型选择适用项。批量规范排查另读“静态批量审查的口径”，按正文类型确定适用规则，关键词只作复核候选，分开报告静态检查、截图覆盖与产品业务验收。

1. 从声明的起点走读内容；检查是否存在凭空出现的概念、材料、权限、数据或步骤。
2. 让关键示例、推导或基础操作与其验收标准一致；课程包含能区分理解与照抄的练习。
3. 验证关键来源、证据、链接、图片和跨文档前置关系，明确尚未验证的部分。
4. 整体按请求的交付物判断完成度：大纲可以完整交付为大纲；缺少关键实操证据的操作课只能标为草稿或待验证。理论教材不因没有软件截图而不合格。
5. 全量逐篇按已确认结构核对约定范围的文档类型、必要内容、正文截图和关键步骤覆盖；必要内容缺项、图片缺失或关键证据不足均阻止完整操作手册通过。类型例外须有内容与用户约定支持，不能按是否缺图反推类型；链接或构建通过不能替代这些检查。
