# 文档配图、画图与插图公共经验

用于学习与培训文档中的场景插画、概念关系、流程、架构和局部说明图。先确定读者需要理解的对象、职责、条件和结果，再安排物件、节点和线条。图能成功生成不等于布局达到交付标准。

以下为这类文档图的默认方案；用户指定风格、已有设计系统和实际业务阅读顺序优先。不要把某次画布大小、像素间距、图稿数量或产品角色写成通用要求。

## 正文字号、颜色与留白先定契约

动笔前确定图的用途、正文显示字号、图片实际承载宽度、已认可色板和同篇留白基准。修改既有图时先读取用户最新确认要求与对应生成规格；生成器默认值、旧审查记录和自然尺寸预览不能覆盖新要求。遇到无法确认先后顺序的冲突，先澄清。

### 字号按实际显示尺寸验收

- 正文内的概念图和说明插图，默认让分区、节点标题与正文显示字号一致，灰色说明比标题小2px，沿用正文系统字体。正文15px时采用标题15px、说明13px；这是显示尺寸，不能直接当作任意SVG的源字号。用户指定独立海报、封面或已有视觉层级时按其要求，不把此规则施加到真实截图或Logo。
- 普通等比缩放SVG可用 `源字号 = 目标显示字号 × viewBox宽度 ÷ 图片实际显示宽度` 计算。仅为一个窄正文宽度反算较大的源字号，会在宽文档视图再次放大；需要多宽度保持同号时，采用已验证的视口补偿或分别生成适配版本，并在各承载宽度验收。
- 验收时测量正文计算字号、图片实际宽度及缩放后的文字尺寸。只查看SVG的 `font-size` 属性、自然尺寸PNG或“文字未溢出”不能证明同字号。CSS视口补偿须在最终嵌入方式下验证；旧SVG查看器和Word/PDF可能不支持，未验证时不能宣称通用兼容。
- 标题与说明依靠颜色、字重及间距建立层级，不靠整体放大文字或缩小灰字掩盖拥挤。已采用的标题字重为500、说明为400，可沿用同篇基线。两行紧邻成组，行距随字号计算，组合与图标共用垂直中心线；字号改变后重新计算换行、节点高度及连线标签避让。

### 颜色沿用已认可的视觉语义

图内主文字使用深色，说明使用可读的灰色；“黑色标题”表示主文字层级，不自动改成纯黑。优先提取同篇主图的主色、文字色、浅底、边界与辅助色，保持层级和业务语义一致。不要给每张图随机换色，也不把统一风格理解为所有类型使用同一种模板。

以下是已采用的蓝灰文档图色板样例；没有既有色板时可参考，其他项目优先使用其已认可配色。场景插画可沿用主色和文字色，体块色按对象与材质选择。

| 用途 | 色值 |
| --- | --- |
| 主蓝／语义图标 | `#356DD6` |
| 主文字／说明文字 | `#243B55` / `#61758C` |
| 辅助连线灰 | `#78889B` |

| 分隔线 | `#DAE3EF` |

### 留白按可见内容边界核对

- 同篇配图先选已认可主图作左右留白基准，测量文字、图标、描边等可见内容的边界；不能仅比较画布尺寸或容器矩形。需要统一时等比缩放、平移，必要时增加高度，保持物件比例并避免裁切。
- 四周保留呼吸空间，领域按内容收尾，不强制等高，也不留下大块无效空白。删除标题、缩短说明后同步收紧区域或重新居中，图标、标题说明组合及箭头仍需对齐。
- 用户要求降低高度时，先调整领域高度、行距与节点间距；保留显示字号、完整业务关系和外边距，不通过压扁整图或缩小文字达成。
- 固定像素属于对应画布的规格。已采用的使用限制图为1160×680、四周24个SVG坐标单位、底部区域80；场景插画为1200宽、内容左界88和右界约1104。这两类图的留白基准不同，不能互相套用，也不能把源坐标留白当成所有显示宽度下的24px。

这些规则用于文档配图、关系图、流程图和说明插图的制作与审查。操作文档的真实截图仍以界面状态为证据，不重绘界面来统一字体或颜色。

## 先区分业务场景插画与关系图

“业务图”不一定是流程图。先判断配图要回答的问题，再选表达；同一篇文章可以有多种图形语言，通过字体、配色和信息层级保持协调，不把全部配图套成同一种卡片与箭头。

| 配图类别 | 回答的问题 | 表达重点 |
| --- | --- | --- |
| 业务场景插画 | 在什么现场，谁使用什么，完成什么业务？ | 真实行业物件与空间为主体，选一个主场景，用少量标签说明用途。机房、园区、站点等应从造型即可辨认。 |
| 概念架构或关系图 | 由什么组成，各方承担什么，如何关联？ | 领域边界、语义图标和必要关系。抽象组件可以使用轮廓图标，不套用场景插画的摆设。 |
| 流程、状态或时序图 | 动作先后、条件分支或消息方向是什么？ | 保留方向、条件和闭环，箭头有业务含义，不能仅为美观删掉。 |
| 局部说明插图 | 一个设备、能力或局部现象是什么？ | 单个对象、局部放大或简洁示意，突出识别特征，不为填满画面补云朵、人物或连接线。 |
| 真实产品截图 | 用户实际看到哪里，怎样操作，得到什么？ | 用对应界面状态证明操作。概念介绍可用插图，操作文档所需的截图证据不能被插图替代。 |

业务场景插画不默认使用架构图的领域框、流程卡片和折线箭头。先用物件位置、主次、邻近标签表达业务；确实需要连接时，再画少量短而淡的线。减少装饰连线不等于删除所有箭头：来源、调用或结果方向影响理解时，用短箭头并就近标明动作或条件。没有顺序含义的独立能力并列展示，不能因连线而误画成必经步骤。删除方向线后仍要说明来源、授权和按需条件，例如“录像来源：设备或边端”“按需视觉分析”。

风格候选应在构图、视角、材质或物件语言上形成真实差异，不只是给同一套方框换颜色。用户要求追加候选时保留已有方案；已有明确选择后直接围绕选定方案优化。色系统一不等于形式一致，轻微体块关系不等于追求强立体、深色渲染或果冻材质。

### 场景与局部插图的造型和信息层级

- 优先画可辨认的行业对象。摄像头应有机身、镜头、安装支架等识别特征，网关应像现场网关，机柜应像设备机柜；不要用通用立方体加圆孔替代所有设备。体块透视一致，结构连接合理。
- 人物不是默认必需元素。需要人物时采用用户选定的人像表达，检查头肩、四肢比例与动作；选择独立半身胸像时只画头、颈、肩胸，不擅自加坐姿、桌椅、手部操作或不自然的下半身。不要把“半身”解释为强行裁断一张全身图。
- 空间视角由任务决定：资源位置适合正俯视园区或楼层，设备空间适合轴测；俯视图用屋顶、道路、绿化和入口建立比例，不画成几块带字的矩形。补充的停车位、庭院等是环境示意，不能写成产品承诺。
- 界面主题也要辨认。空间态势插图优先表达底图、点位、选中区域和对应现场信息；不要默认塞入柱状图、折线图。指标趋势才使用合适图表。插画屏幕不能冒充真实产品截图，也不凭空增加按钮或操作能力。
- 用一个主要视觉焦点和少量辅助对象。不要堆多个剪贴纸块、复杂人物动作、等权标题或交叉连线。图内标题深色、较大，解释文字较小、颜色较轻；文档已经说明的长条件放在正文，影响读图的短条件就近保留。
- 配色先与同篇已认可的主图协调，再决定各图的结构。不要依次为每张图创造一套色系，也不要靠全图相同卡片、同样图标排列制造“统一”。

先在整篇正文中并排或连续查看配图，再判断单张图是否成功。逐图检查物件识别、主次、人物比例、文字实际显示尺寸、箭头必要性与业务含义；纯 SVG、可重复生成和构建成功仅是技术条件，不代表插画质量达标。

## 先确定业务关系，再规划版面

- 列出参与方、业务节点、输入输出、关系方向、条件、可选分支与失败恢复。重绘时保留原节点与关系基线，视觉分组不增加业务步骤或改变依赖。
- 多方交互优先左、中、右：来源或提供方 → 平台处理或映射 → 消费方与结果。双向交互明确区分上报与下发。不要为凑三列虚构一个参与方。
- 业务侧内部可上下串联步骤，领域内部可再细分。内容均衡且文字有足够宽度时并列；明显不均衡时改为上下，避免一侧撑高、另一侧留下大块空白。
- 同一参与方占多个领域时，不必与其他侧等宽。按标题长度、说明行数、节点数和关系密度分配宽度；容器按自身内容收尾，不强制等高。
- 业务侧紧邻，只预留容纳箭头和动作标签的通道。先解决分组与比例，再考虑加大画布；不能靠把所有内容缩小来容纳复杂图。
- 内容过密时拆成总览与局部图，保留相互定位。单一顺序流程或状态机可选择更适合的结构，无需强套多侧布局。

## 按图的目的选择图形表达

统一字体、线宽、图标体系和配色秩序，不等于把所有图画成同一种卡片。架构图回答组成与职责，流程图回答动作与先后，状态图回答变化条件，时序图回答参与方消息顺序；先选合适表达，再排版。

- 架构图用浅色实线边框划分业务领域，组件可用语义图标、名称和灰字直接组织，不给每个组件默认套白底卡片。按需使用设备外形、数据库圆柱或服务组，图形应表达真实对象。
- 流程图用清楚的步骤框和方向箭头；完成节点可用圆角胶囊，真实决策可用判断形状并在线上标条件。配置规则本身不自动等同于决策节点，不能为装饰凭空增加分支。
- 领域可以有很淡的底色，边界连续且清楚；节点与领域避免层层强底色、粗边框和多重容器。局部卡片需要突出一个动作时可以保留，不把白底当成通用要求。
- 文档已提供标题与解释时，图内不再重复文档标题、副标题、通用备注或“实线/虚线表示……”脚注。图内保留参与方、节点、动作和影响理解的业务条件；线型意义尽量通过“按需通知”等关系文案直接表达。
- 产品概念图用陈述性文案表达对象、职责、约束和关系，避免“先确认”“分别看”“按需选择”等让客户自行判断的引导语；保留影响理解的具体条件。操作教学图的真实动作标签按任务需要保留。

分区标题回答“哪一侧、哪个领域”；节点包含“语义图标 + 业务名称 + 灰色简短说明”。灰字位于节点标题下面，解释职责、产出或关键条件。分区头保留简洁标题，避免再堆一层重复说明。

- 标题用业务对象或动作，正文深色；灰字用一句短语，通常一至两行。不用灰字重复标题，不填“进行相关处理”等空话。
- 说明按节点真实含义逐项编写；不能把一整侧的职责机械复制给每个节点。影响选择的条件仍须明确，不能为短句删除关键边界。
- 图标与文字之间、标题与说明之间保持统一间距。卡片高度按实际行数计算，卡片内留白紧凑且有呼吸空间。
- 双列卡片先扣除图标、左右内边距，按剩余文字宽度判断是否适合并排。长标题被拆成三四行或说明碎成短条时，加宽或改单列。
- 中文换行避免末行只剩一字，按词组拆分动作；英文标识尽量保持完整。不能通过小到难读的字号隐藏拥挤。

## 图标与视觉语言

- 同一平台复用一套轮廓图标、线宽、圆角、字体和色彩语义。可借鉴云厂商架构图的清晰分区与图形层级，不直接复制品牌标识。
- 按对象或动作选择图标：设备、摄像头、网关、人员、项目、数据库、规则、凭据、计划、上传下载、模型服务、统计和验收应可区分。同类业务保持同类图标，不为追求每块不同而随机分配。
- 图标表达节点语义，颜色表达已有分区或业务语义；不要用同一个云朵或通用配置图标代替全部业务，也不单靠颜色区分对象。
- 优先沿用客户已认可的项目色系。明快的图标、标题与浅色领域底可以同时保持协调；不要把“限制混色”误解为降低所有颜色饱和度或统一成灰蓝。颜色服从业务分组与主次，不给每个节点随机上色，不按左中右机械分配固定颜色。可自配协调组合，不要求复制参考厂商品牌色。

## 官方图稿参考的提炼方法

参考图用于学习表达，不作为本产品业务事实。看清读者怎样识别领域、对象、动作和分支，再提炼到自己的设计；不照搬品牌标识、整张构图或配色。

- [阿里云物联网产品架构](https://help.aliyun.com/zh/iot/product-overview/service-architecture)：设备端、平台能力、外部云服务分区明确；用具体设备与网关图标、中央能力矩阵形成层级。该历史产品文档仅作视觉参考。
- [阿里云物联网工作原理](https://help.aliyun.com/zh/iot/product-overview/what-is-iot-platform)：设备、平台、服务器与应用之间的箭头直接说明上下行协议和动作；存储形状与服务对象有区别。
- [AWS Step Functions 入门](https://docs.aws.amazon.com/step-functions/latest/dg/getting-started.html)：起点、任务、判断、等待和并行域使用不同形状或图标，分支在线上标条件。借鉴其语义区分，不把所有业务都变成状态机。

## 连线可读性与语义

- 相邻侧的同源分发、同目标汇集可以共用主干，减少错落平行的折线。只有方向、条件与关系含义相容时才合并；共享几何线段不能误画成新增业务汇合节点。
- 成功与失败、上报与下发、必经与可选分支分别保留。箭头端点清楚落在对应节点，不穿过其他业务块或标题。
- 连线标签默认透明底，不套白色或彩色底块；线条在标签附近断开，避免穿过文字。标签和编号都必须位于相应业务域或预留通道内，不能越界。
- 线上标简短动作，如“同步身份”“属性上报”“下发版本”“执行回传”；同一主干的相同动作可只标一次。标签放在读者能对应到该关系的位置，不能为了避碰漂到无关分支旁。
- 长条件放在对应关系旁，或结合真实决策节点表达；过密时拆局部图。可选属性、完整条件与方向不能只藏在机器元数据里，不能以清理脚注为由删除影响判断的条件。
- 同侧相邻步骤用短箭头。跨多个块的次要引用关系可改为来源卡片底部“动作 → 目标”，但若这会掩盖关键分支或闭环，则重排或拆图保留显式路径。
- 双列节点避免蛇形排列造成阅读方向反复变化；先保持局部从左到右、从上到下易读，再决定连线方式。

## 生成、复用与交付核查

优先复用项目已有矢量图与生成器。需要可重复生成时，将业务内容、呈现配置与共享绘图能力分开维护；一次性小图无需新建通用引擎。适合文档和导出的图优先使用自包含SVG，避免依赖远程字体、外链图片或未验证的foreignObject。

文档正文内的业务图默认使用容器100%宽、保持纵横比，提供放大入口。该规则不扩展到Logo、图标或所有截图。宽度撑满后仍需检查文字实际可读性；手机窄屏可放大查看，不能仅用“图片没溢出”宣称可读。

交付前完成与本次改动相称的核查：

1. **业务保真**：对照节点、边、条件、可选属性和角色边界；只改布局或图标时，业务定义应保持一致。示意图不充当真实产品操作或结果证据。
2. **全图视觉检查**：批量图全量渲染，联系表检查整体风格和比例，密集图、回流图及长标题另行放大。发现文字裁切、缺字、单字孤行、线压块、标签压字或显著无效留白时继续调整。
3. **自动几何检查**：生成器存在时可校验文字边界、标签互碰、标签与节点及分区头碰撞。几何检查通过仍需人工判断阅读顺序、关系可辨性与美观。
4. **实际承载效果**：在常规正文与宽文档视图中检查图片加载、中文、标题和说明显示字号、颜色层级、成组居中及四周留白，再检查代表性手机视口。已采用的双宽样例为592px与1250px；其他站点按实际承载宽度取样。目标包含Word或PDF时，从实际导出入口取样渲染，检查图标、灰字、箭头、整图边界与分页，不只检查源SVG或文字提取。
5. **发布完整性**：检查图片引用与相关构建。区分图稿验证、文档排版验证和产品业务验收；如宽表或其他既存问题未修复，交付说明应准确限定通过范围。

图稿与文档发布内容只保留客户需要的信息。检查命令、临时截图、一次性数据规模与调试流水留在任务证据，不写入客户说明或本通用规范。
