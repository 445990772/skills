# JetLinks SaaS 教材产品边界

本文件只适用于 JetLinks SaaS 学习资料。它保存本轮已经确认、会持续影响教材结构的产品边界。具体菜单、字段、角色选项和状态过滤仍要在每次编写时以当前 UI、接口和代码复核，不能把这里当成版本无关的静态接口文档。

## 系统与数据边界

1. **SaaS 平台**维护账号、平台角色、运行区域、服务、规格、项目关系和订阅等控制面数据。
2. **Runtime 系统**维护设备、产品、接入、规则、告警、空间和项目业务用户等运行数据。
3. SaaS 控制面与 Runtime 业务数据使用不同数据库边界，通过 Runtime Agent、项目标识、用户映射和接口衔接，不能写成共用同一套业务表。
4. 同一 Runtime 内的多个项目通常共享物理数据库并按项目或租户标识及资产权限进行逻辑隔离。除非部署事实另有证据，不能写成每个项目必然拥有独立数据库。

## 平台、项目与项目应用

1. **平台层**准备账号、区域、可订阅服务、规格和公共资源。
2. **项目层**承接运行区域、服务订阅、项目所有者、项目管理员和资源额度。
3. **项目应用层**在项目已有能力和权限范围内进一步组织应用成员、应用角色、菜单和资产范围。
4. 功能不经过项目应用层时，要明确说明该流程直接作用于项目范围；不能让读者猜测应用层是否遗漏。

以下对象名称相近但不能混用：

- **SaaS 应用方案**：创建 SaaS 项目时可选择的初始化方案。
- **项目应用**：Runtime 项目内部的业务工作空间。
- **项目应用模板**：约束项目应用可用菜单和资产策略的模板。
- **应用中心资源**：模块、场景包、设备库和可视化等可加入项目的资源。

## 账号、角色与项目关系

1. **平台运营管理员**是教材业务称谓，表示取得 SaaS 运营端相关菜单和操作权限的账号，不应直接写成代码内固定角色。
2. SaaS 用户创建后只获得登录身份。用户自行创建项目或在项目创建流程中被指定为所有者后，才产生项目所有者身份。
3. 项目管理员来源于用户与指定项目的成员关系，不等于平台运营管理员，也不自动拥有其他项目权限。
4. SaaS 平台角色、项目所有权或成员关系、Runtime 角色和项目应用角色属于不同授权层，教材必须分别说明创建入口和生效范围。
5. 当前页面是否开放普通成员、客户或其他成员类型必须重新检查 UI；后端存在枚举不能证明用户能从页面完成操作。

## 区域、服务与规格

1. SaaS 的 **服务**是可订阅能力定义，不等于某个 Runtime 微服务进程。
2. 区域、服务和规格共同形成项目可选择和订阅的能力。服务和规格只有低信息量增删改查时，应与区域配置合并讲解。
3. 服务依赖、编码、区域 ID、访问密钥、Runtime 菜单和资产类型属于字段来源或设计说明；没有独立用户动作时不要提升为主步骤。
4. Runtime 与 SaaS 服务的数量关系必须核对当前实体、接口和 UI 后再写，不能凭名称推断一对一。

## 已确认的基础教学顺序

平台运营管理员的基础目录按真实工作顺序组织：

1. 工作台
2. 系统管理
3. 运营中心
4. 支付中心
5. 开发中心
6. 应用中心

进入项目后，再切换到项目所有者、项目管理员、Runtime 业务用户和项目应用成员等实际接收角色。不同角色的菜单名称和布局必须分别核对，不得复用平台管理员目录或截图。
